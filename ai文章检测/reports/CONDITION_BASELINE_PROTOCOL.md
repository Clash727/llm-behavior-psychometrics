# Condition-prefix and human-reference baseline

## Scope and data boundary

This protocol uses only the frozen audited training pool: `artifacts/audited_train/splits/train.jsonl` (85,369 rows) and `dev.jsonl` (13,387 rows). It never opens `locked_test.jsonl`, official validation data, or external data. The source pool remains the existing final train/dev split. The earlier source-balanced experiment remains paused.

All split decisions operate on connected components built from `article_id`, every `duplicate_article_ids` value, `body_hash`, and every `alias_body_hashes` value. The implementation reuses `ood.connected_components`, which also keeps all transitive links together. Every persisted manifest row contains only original split/index, component id, role, label, row key, and SHA-256 of the text; it never contains full text.

## Frozen role design

For the IID original train, a single deterministic assignment with seed `20261019` creates R/F/S roles at row-count targets 20/60/20 percent. R/F/S all consist of complete connected components and do not overlap. An R component may contain both labels; only its human rows (label 0) fit the reference distribution, and machine rows in R are retained in the manifest but unused for reference fit or classifier fit. F fits the LR/HGB classifiers; S selects only between those two predeclared classifier families at threshold 0.5. The implementation raises an error if F or S lacks either label; it never retries another seed. All original dev rows have role `DEV`: the already-fitted R human reference is applied to dev without refitting or selecting anything there.

For generator-family and domain OOD studies, first use the existing OOD protocol to form each target's own train/dev/eval rows. Map the existing subsets back to frozen rows by original split, label, and body hash, then independently split only that target's OOD train rows into R/F/S with the same fixed algorithm and seed. Only human rows inside that OOD R fit its human reference; no IID R row may be imported. The OOD held evaluation remains separate. These OOD model comparisons are development stress tests because the pressure sets have already informed development; they are not blind confirmation.

## GPU feature contract and row alignment

The frozen base-model condition probe is an extraction artifact, not a learned detector. It scores the same first 448 body token IDs in `raw`, `neutral`, `human_hypothesis`, and `machine_hypothesis` contexts. Each article-condition forward pass is singleton (`scoring_batch_size=1`, `single_article_forward_per_condition_no_mixed_padding`) to avoid cross-article padding effects; storage shard size does not change scoring. CPU joins the probe's `rows.jsonl` against the manifests via `row_key`, original split/index, and `text_sha256`; every expected source row must match exactly once, and every probe row must match the frozen source. Four-condition and run-completion metadata, input hashes, scoring policy, and body budget are checked before fitting. Smoke/pilot/partial runs cannot enter the formal analysis. The probe's source/generator metadata is retained only for auditing and subgroup reporting, never as a model input or a routing key.

## Fixed comparisons

- **A:** raw-context token surprise summaries (mean, standard deviation, quantiles, scored-token count) only.
- **B:** A plus body-only features: character and whitespace-token lengths, log lengths, whitespace count, Unicode letter/script/digit/punctuation/whitespace ratios. Script fields are coarse script proxies, not language identification. The body-token-length bucket comes from the probe's token count; dominant script proxy is derived from text. These two keys define D reference cells and never enter the classifier as categorical metadata.
- **C:** B plus neutral, human-hypothesis, and machine-hypothesis responses relative to raw/neutral, including aggregate and aligned 16-token-window response differences. Condition roles are fixed for every row; no true label/source/generator/language is used to choose a condition.
- **C-neutral control:** B plus only the neutral-minus-raw response. This predeclared CPU-only control isolates the generic prefix effect from the human/machine hypothesis contrasts; it uses the same GPU rows and adds no GPU extraction or model search.
- **D:** C plus empirical percentile and robust z-score for each continuous C feature against human R. Reference cells use body-token-length bucket and dominant script; cells with fewer than 200 human references fall back to global human R. Robust scale is 1.4826*MAD, with global MAD, IQR, then unit-scale fallback for zero/degenerate MAD.
- **D-global control:** C plus empirical percentile and robust z-score using the same R human rows but one global reference, without length/script cells. D and D-global therefore use the same additional human labels; their difference tests the value of conditional reference cells.

The B/C-neutral/C/D-global/D feature matrices are shared-prefix supersets and keep the same rows, 448-token budget, and F/S split. Per-window means use fixed 28-window slots and valid-token counts; missing windows have mean/count zero, so no split-specific feature selection occurs. No cached 512-token aggregation is accepted. No Qwen prediction fusion is fit: there are no OOF predictions. Each of the six sets is evaluated with LR (`C=1`) and HGB (15 leaves, 300 iterations); S selects only LR or HGB per comparison set by `0.7*macro_F1 + 0.3*short_macro_F1`, where short means fewer than 100 whitespace tokens. If S has no short rows, its short term falls back to all-row macro F1 and is explicitly marked. There is no other parameter search. If the IID S signal is absent, do not widen the grid or start template B; return the negative/uncertain result for parent review.

R is role-isolated from F/S but its human rows provide additional label-informed reference statistics for D and D-global. Thus D-versus-C combines feature changes with extra human reference supervision; it cannot alone establish the value of condition-prefix responses. C-neutral isolates generic prefix response, and D-global shares the same human R label budget as D to isolate conditional reference cells. Report this supervision difference with all results.

## Saved evidence and report rules

A formal run preserves split manifests and split audit, all input/config/code/dependency hashes, run log, fitted feature/reference transforms and models (`joblib`), numeric feature arrays and CDF/median/MAD coefficients, per-row probabilities/labels/IDs, selection scores, ROC points, calibration bins, paired connected-component bootstrap draws (200 replicates, seed `20261020`), plotting CSVs, and a concise report. Start the released run through `scripts/run_condition_baseline_supervised.py`; it takes an OS file lock, writes a sidecar state record with supervisor/child PID and process start ticks before fitting, and keeps a persistent supervisor log. Existing state or nonempty output is never overwritten, so an interrupted run requires explicit review before recovery. CPU execution bounds OpenMP/BLAS pools to two threads across fitting, prediction, and bootstrap. Only hashes/IDs and numeric features are exported; full text is not copied into experiment artifacts. A synthetic fixture run is clearly marked `synthetic_engineering_fixture` and cannot be reported as an empirical result.
